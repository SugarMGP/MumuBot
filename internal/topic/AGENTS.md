# AGENTS

本目录负责话题工作记忆：消息归属、活跃话题、摘要刷新、归档话题召回和给 agent 的话题上下文。

## 入口与职责

- `manager.go`：话题管理器、运行队列、启动恢复、消息持久化和上下文组装。
- `assignment.go`：批量话题归属的提示词、模型输出解析和结果应用。
- `store.go`：数据库和向量存储访问，承担消息日志、话题线程、摘要快照等持久化。
- `prompt.go`：给模型看的话题上下文渲染。
- `scoring.go`：候选话题打分和召回辅助。

## 语义边界

- 话题工作记忆是主路径能力，不加可关闭开关，也不为主链路补可选兜底。
- 话题归属、摘要、检索词生成只使用原始文本；原始文本为空的消息不进入模型分配队列。
- 模型漏返回、返回非法动作、候选话题无效、新话题编号缺失或模型调用失败时，快速标记为 `no_topic` 并记录日志，避免长期卡住学习链路。
- 存储层失败要暴露真实错误；只有数据库确实写入 `no_topic` 成功后，才能清理内存里的 pending 状态。
- 批量归属完成后必须清理已写入最终状态的 pending 消息；数据库写入失败时保留内存 pending，等待后续调度。

## 提示词与结构化输出

- 话题归属提示词必须约束模型不要重复返回同一个 `message_key`。
- 如果模型仍重复返回同一个 `message_key`，解析层可以按现有规则以后者为准，但要保留日志，方便追查模型行为。
- `keywords`、事实、未完事项等列表字段必须按结构体要求返回数组，不要把逗号分隔文本当成列表。

## 修改注意

- 队列压力、关闭中、模型失败都不能伪装成“已处理但无结果”。
- 摘要刷新不能跨过仍在 pending 的消息。
- 消息清理不能删除已分配话题的消息。
