# AGENTS

本目录负责持久化和检索：MySQL 数据表、Milvus 向量存储、长期记忆、消息日志、成员画像、风格卡片和表情包记录。

## 入口与职责

- `manager.go`：数据库、向量存储、迁移和后台清理任务初始化。
- `memory_ingest.go`：长期记忆 claim（结构化事实候选）提取、校验、合并和写入。
- `memory.go`：长期记忆查询、状态流转和基础操作。
- `message_log.go`：群消息日志、话题处理状态、learner 可消费前缀。
- `member_profile.go`、`member_name_record.go`：成员画像和成员名记录。
- `style_card.go`、`jargon.go`、`sticker.go`：群文化和表情包相关数据。

## 数据边界

- 长期记忆只接收有效 claim；空内容、无效类型、证据不足时跳过并记录日志。
- 自动长期记忆写入只由话题摘要链路触发；learner 不写长期记忆。
- 成员画像保持全局 `user_id` 维度，除非明确需求，不引入 `group_id` 隔离。
- 消息日志的展示内容不能反向作为语义输入；语义链路必须读取原始文本字段。

## 存储规则

- 向量写入和数据库状态要表达真实结果，不做兜底写库。
- 清理旧消息时不能删除已分配话题的消息，也不能删除 learner 尚未处理的消息。
- 迁移、清理、衰减这类后台任务要可重复执行，不依赖一次性内存状态。

## 修改注意

- 新增字段要先确认是否属于长期记忆、话题、学习或后台展示，不要把多个职责塞进同一模型。
- GORM（Go 的数据库 ORM）模型变更后要检查自动迁移和历史数据兼容影响。
